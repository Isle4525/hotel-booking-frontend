# 🏨 Booker — Платформа бронирования отелей

Современное SPA-приложение на **React 19** и **Vite** для поиска и бронирования номеров в отелях Казахстана. В проекте есть каталог с фильтрами и поиском, корзина с расчетом стоимости, демонстрационные регистрация и вход, сохранение состояния в `localStorage` и переключатель светлой/темной темы.

> Хотите изучить React на примере этого проекта? Начните с подробного учебного разбора в [STUDY.md](./STUDY.md).

## 🏗 Архитектура проекта и Context API

Приложение построено из React-компонентов. Context API используется для общего состояния темы, авторизации, навигации и корзины. Это помогает компонентам получать данные без передачи их через каждый промежуточный компонент («prop drilling»).

```
                           [ App.jsx ]
                                |
                        <AppProviders>
    (ThemeProvider + AuthProvider + NavigationProvider + CartProvider)
                                |
                         [MainContent]
                                |
        +-----------------------+-----------------------+
        |                       |                       |
    <Header />                <main>              <BookingCart />
 (useAuth, useCart,      (useNavigation)       (useAuth, useCart,
  useNavigation)                |                useNavigation)
                 +--------------+--------------+
                 |              |              |
              'home'         'login'       'register'
                 |              |              |
          [Hero, HotelList,   <Login />    <Register />
             Services]
                 |
            <HotelCard />
              (useCart)
```

### Зачем нужны контексты:
- Общие данные доступны вложенным компонентам без длинной цепочки промежуточных props;
- **Изоляция ответственности**: состояние корзины, авторизации и навигации разделено по специализированным контекстам;
- **Удобные хуки**: любой дочерний компонент может получить нужные данные в 1 строчку: `const { currentUser } = useAuth()`, `const { addToCart } = useCart()`, `const { navigate } = useNavigation()`;
- Некоторые компоненты также принимают props для переопределения обработчиков и данных.

## 🧠 Контексты приложения (`src/context/`)

Контексты и провайдеры находятся в **`src/context/`**. Provider хранит состояние и предоставляет его вложенным компонентам; хуки `useTheme`, `useAuth`, `useCart`, `useNavigation` дают удобный доступ к соответствующему контексту.

```
src/context/
├── ThemeContext.js        # Определение контекста темы
├── ThemeProvider.jsx      # Состояние темы, DOM-атрибут и localStorage
├── useTheme.js            # Хук доступа к теме
├── index.js               # Единая точка реэкспорта провайдеров и хуков
├── AppProviders.jsx       # Корневой композитный провайдер
├── AuthContext.js         # Определение контекста авторизации
├── AuthProvider.jsx       # Провайдер состояния пользователя
├── useAuth.js             # Хук доступа к данным и методам авторизации
├── CartContext.js         # Определение контекста корзины
├── CartProvider.jsx       # Провайдер состояния корзины и калькулятора
├── useCart.js             # Хук управления номерами и подсчетом цен
├── NavigationContext.js   # Определение контекста навигации
├── NavigationProvider.jsx # Провайдер роутинга между экранами и скролла
└── useNavigation.js       # Хук переключения страниц и плавного перехода к секциям
```

### 1. `AuthContext` (`useAuth`)
Предоставляет состояние и методы аутентификации:
- `currentUser` — текущий вошедший пользователь (`null` для гостя);
- `isAuthenticated` — булевый флаг авторизации;
- `login(email, password)` — валидация и вход пользователя;
- `register(userData)` — регистрация нового аккаунта;
- `logout()` — выход из профиля и сброс сессии;
- `setCurrentUser(user)` — прямое обновление состояния;
- `defaultDemoUser` — тестовые учетные данные по умолчанию.

### 2. `CartContext` (`useCart`)
Предоставляет функционал корзины и умного калькулятора:
- `cartItems` — список номеров с параметрами (`roomsCount`, `nights`, `selected`);
- `cartOpen` / `openCart()` / `closeCart()` / `toggleCart()` — управление состоянием модальной шторки;
- `addToCart(hotel)` — добавление отеля в корзину;
- `updateCartItem(hotelId, changes)` — обновление количества комнат, ночей или выбора;
- `removeCartItem(hotelId)` — удаление отеля из корзины;
- `clearCart()` — полная очистка корзины;
- `getInCartCount(hotelId)` — количество забронированных комнат для бейджа карточки;
- `cartCount` — общее число отелей в корзине (для бейджа в Header);
- `totalRooms` / `totalPrice` — автоматический пересчет комнат и итоговой стоимости в тенге (`₸`).

### 3. `NavigationContext` (`useNavigation`)
Предоставляет легкий клиентский роутинг без тяжелых сторонних зависимостей:
- `currentPage` — текущий активный экран (`'home'`, `'login'`, `'register'`);
- `navigate(page, targetSectionId)` — переход на экран с автоматическим плавным скроллом к указанной секции (`hero`, `hotels`, `services`, `contact`);
- `isHome`, `isLogin`, `isRegister` — вспомогательные флаги для подсветки активных ссылок в меню.

### 4. `AppProviders` (Композиция провайдеров)
Объединяет все контексты в единую чистую обертку:
```jsx
export default function App() {
  return (
    <AppProviders>
      <MainContent />
    </AppProviders>
  );
}
```

Провайдеры вложены в `AppProviders.jsx`: `ThemeProvider`, `AuthProvider`, `NavigationProvider`, `CartProvider`. Поэтому компоненты внутри этой обертки могут использовать все четыре контекста.

## 🔄 Четыре сценария с useEffect

1. **Загрузка и сохранение корзины:** `CartProvider.jsx` читает начальное значение из `localStorage`, а эффект записывает корзину при каждом изменении.
2. **Поиск с debounce:** `HotelList.jsx` ждет 500 мс после ввода. Если пользователь продолжает печатать, предыдущий таймер очищается.
3. **События браузера и cleanup:** `BookingCart.jsx` и `HotelList.jsx` обрабатывают Escape, пока открыт диалог; `Header.jsx` подписывается на изменение размера окна. Обработчики снимаются в cleanup-функциях.
4. **Тема:** `ThemeProvider.jsx` при изменении темы сохраняет ее и ставит атрибут `data-theme` на корневой HTML-элемент. CSS выбирает цвета по этому атрибуту.

Подробные разборы этих примеров и основ React есть в [STUDY.md](./STUDY.md).

## 🔐 Демо-аутентификация и профиль пользователя

### Страница регистрации (`Register`)
Форма регистрации содержит:
- **Full Name** (ФИО пользователя);
- **Email Address**;
- **Password**;
- **Confirm Password**;
- **Чекбокс согласия** с правилами и условиями («Terms and conditions»);
- **Кнопку «Create Demo Account»**;
- **Переход на страницу входа** («Already have an account? Log In»).

#### Валидация:
- Обязательность всех полей и проверка длины имени;
- Синтаксис email через регулярное выражение (`name@domain.ext`);
- Пароль не менее 8 символов;
- Сверка совпадения пароля и подтверждения;
- Обязательное согласие с правилами;
- Проверка на уникальность email в демо-базе `localStorage`;
- Инлайн-ошибки под полями с автоматическим снятием при вводе;
- Карточка подтверждения успешной регистрации с возможностью войти в 1 клик.

### Страница входа (`Login`)
Форма авторизации содержит:
- **Email Address**;
- **Password** с кнопкой скрытия/показа символов (👁️);
- **Кнопку «Log In»**;
- **Кнопку автозаполнения «Quick Fill Demo Credentials»** в 1 клик;
- Валидацию и понятные оповещения об ошибках / успехе входа.

### Тестовые данные демо-аккаунта
- **Email:** `demo@booker.kz`
- **Пароль:** `Password123`

*(Все новые пользователи, зарегистрированные через форму, также сохраняются в `localStorage` и могут повторно авторизоваться).*

### Интеграция с корзиной и защита чекаута
- Корзина сохраняет свое состояние при любых переходах между страницами входа, регистрации и каталога.
- **Защита бронирования**: при нажатии на «Book Now» неавторизованным гостем выводится окно с требованием авторизации и быстрыми кнопками входа / регистрации. Авторизованный пользователь сразу получает именной ваучер бронирования.

## 🎨 Организация стилей (CSS Architecture)

Все CSS-стили проекта строго вынесены в директорию **`src/styles/`**:

```
src/styles/
├── index.css        # Дизайн-токены, переменные, глобальный сброс и кнопки
├── App.css          # Базовые стили приложения
├── Auth.css         # Стили страниц входа, регистрации, инлайн-ошибок и алертов
├── Header.css       # Шапка, профиль пользователя, кнопки входа и счетчик корзины
├── Hero.css         # Главный промо-баннер и поиск
├── HotelList.css    # Фильтры категорий, каталог и модальные окна
├── HotelCard.css    # Карточки отелей, бейджи, цены и кнопки действий
├── BookingCart.css  # Выдвижная панель корзины, калькулятор и защита чекаута
├── Services.css     # Сетка услуг и преимуществ
└── Footer.css       # Подвал сайта
```

Компоненты интерфейса находятся в `src/components/`, контексты — в `src/context/`, стили — в `src/styles/`.

## 🚀 Ключевой функционал

### Каталог и фильтрация по кнопкам
- Динамическая фильтрация отелей по категориям (`Luxury Hotel`, `Mountain & Ski`, `Business Hotel`, `Resort & Beach` и др.).
- Автоматический расчет уникальных категорий через `new Set()`.
- Клик по активной кнопке сбрасывает фильтр ко всем отелям (`All`).
- Подсчет найденных отелей и кнопка быстрого сброса.

### Карточки отелей
- Фотографии, рейтинг, город, удобства и цена.
- Модальное окно подробной информации («Details»).
- Кнопка «+ Add Room» для быстрого добавления в корзину с обновлением бейджа «✓ In cart».

### Корзина и автокалькулятор (`BookingCart`)
- **Мультибронирование**: одновременный выбор нескольких отелей.
- **Степперы**: количество номеров (1–20) и ночей (1–30).
- **Чекбоксы выбора**: включение/исключение отелей из общего расчета стоимости.
- **Автоматический пересчет**: итоговая сумма в тенге (`₸`) пересчитывается мгновенно в контексте.

## ⚠️ Безопасность и ограничения демо-режима

> **Важно:** Модуль аутентификации является демонстрационным интерфейсным решением (**Frontend Demo Flow**). Данные хранятся локально в `localStorage` браузера для демонстрации клиентской логики и валидации. Не используйте реальные пароли или платежные данные.
