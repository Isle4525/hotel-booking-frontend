# React с нуля: подробный разбор проекта Booker

Этот материал предназначен для читателя, который раньше не писал на React. Здесь шаг за шагом объясняются компоненты, JSX, props, state, хуки, эффекты, контексты, события, `localStorage` и то, как эти идеи используются в Booker.

## 1. Что мы создаем и где работает приложение

Booker — сайт-каталог отелей. Посетитель может просматривать отели, искать и фильтровать их, добавлять варианты в корзину, менять количество комнат и ночей, входить в демо-аккаунт и выбирать тему оформления.

Это frontend-приложение: интерфейс и его логика работают в браузере. Здесь нет настоящего сервера и базы отелей. Файл `src/data/hotels.js` содержит демонстрационный каталог, а браузерное хранилище `localStorage` запоминает некоторые данные на устройстве.

React — библиотека JavaScript для построения пользовательских интерфейсов. Вместо того чтобы вручную искать элементы страницы и менять их, мы описываем интерфейс как функцию от данных. Когда данные изменяются, React обновляет нужную часть страницы.

Vite — инструмент, который запускает проект во время разработки и собирает его для публикации. Команда `npm run dev` запускает локальный сервер; `npm run build` создает оптимизированную сборку.

## 2. JavaScript, HTML и JSX

Браузер отображает HTML. JavaScript добавляет поведение: реагирует на клики, хранит значения, выполняет вычисления. React соединяет эти части, а JSX позволяет описывать похожую на HTML разметку прямо в JavaScript-файлах.

Например:

```jsx
function Greeting() {
  const name = 'Алия';
  return <h1>Здравствуйте, {name}!</h1>;
}
```

Фигурные скобки `{}` внутри JSX означают: «вставить сюда JavaScript-выражение». JSX — не обычный HTML: например, атрибут CSS-класса называется `className`, а обработчик клика записывается как `onClick`.

## 3. Компоненты: детали конструктора

Компонент — функция, которая возвращает часть интерфейса. Имя компонента принято писать с заглавной буквы. Один компонент может показывать кнопку, другой — карточку отеля, третий — целую страницу. Компоненты можно вкладывать друг в друга и повторно использовать.

```jsx
function HotelCard() {
  return <article>Карточка отеля</article>;
}

function HotelList() {
  return (
    <section>
      <HotelCard />
      <HotelCard />
    </section>
  );
}
```

В проекте `src/App.jsx` собирает общую структуру, `src/components/Header.jsx` отображает шапку, `HotelList.jsx` — каталог, а `HotelCard.jsx` — отдельную карточку. Вызов `<HotelCard />` выглядит как HTML-тег, но это вызов React-компонента.

Компонент описывает интерфейс, а не создает его вручную. Не нужно писать команды вроде «найди элемент с таким id и вставь в него текст». Вместо этого задается разметка, а React сам согласует ее с браузером.

## 4. Props: входные данные компонента

Props (сокращение от properties) — данные, которые родительский компонент передает дочернему. Их можно представить как аргументы функции. Например, карточка должна получить данные конкретного отеля:

```jsx
function Greeting({ name }) {
  return <p>Привет, {name}!</p>;
}

<Greeting name="Алия" />
```

`name="Алия"` — prop. Внутри компонента он читается из объекта props. Props позволяют одному и тому же компоненту показывать разные данные. В списке это особенно полезно: одна карточка-компонент отображает первый отель, другая — второй.

В `HotelList.jsx` карточке передаются данные и функции:

```jsx
<HotelCard
  key={hotel.id}
  hotel={hotel}
  onBook={handleBook}
  onAddToCart={onAddToCart}
/>
```

Значения в фигурных скобках — JavaScript-переменные. `hotel` содержит сведения об отеле, `onBook` и `onAddToCart` — функции, которые карточка может вызвать. Функция тоже может передаваться через props.

Условный рендеринг означает показать одну разметку при одном условии и другую при другом:

```jsx
{currentUser ? <p>Вы вошли</p> : <p>Гость</p>}
```

В приложении `App.jsx` показывает `Login`, `Register` или домашнюю страницу в зависимости от `currentPage`. В JSX также можно создать повторяющиеся элементы через `.map()`. Для повторяющихся элементов React нужен стабильный prop `key`, обычно уникальный id.

## 5. События: как интерфейс отвечает пользователю

Событие — действие, о котором браузер сообщает приложению: клик, ввод текста, нажатие клавиши, изменение размера окна. В React обработчик события — функция, связанная с элементом.

```jsx
function Example() {
  function handleClick() {
    alert('Кнопка нажата');
  }

  return <button onClick={handleClick}>Нажми</button>;
}
```

Важно передавать функцию, не вызывая ее немедленно: `onClick={handleClick}`. Запись `onClick={handleClick()}` вызвала бы функцию во время построения интерфейса.

Для ввода часто используют событие `onChange`. Его объект события содержит `event.target` — элемент, вызвавший событие; `event.target.value` — введенное значение. В `HotelList.jsx` обработчик передает это значение в `handleSearchChange`.

## 6. State: память компонента

State (состояние) — данные, которые могут меняться, и от которых зависит отображение интерфейса. Например, выбранная категория, текст поиска, открыта ли корзина. Обычная локальная переменная не подходит: ее изменение само по себе не заставляет React заново отобразить компонент.

Для состояния используется хук `useState`:

```jsx
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      Нажато раз: {count}
    </button>
  );
}
```

`useState(0)` создает состояние со стартовым значением 0. `count` — текущее значение, `setCount` — функция обновления. Когда вызывается `setCount`, React сохраняет новое значение и повторно вызывает компонент для обновления интерфейса.

Если новое значение вычисляется на основе старого, надежнее передать функцию:

```jsx
setCount((previousCount) => previousCount + 1);
```

React применит ее к последнему значению состояния. Объекты и массивы обычно обновляют созданием новых значений, а не изменением старых на месте:

```jsx
setItems((previousItems) => [...previousItems, newItem]);
```

В `HotelList.jsx` есть несколько независимых состояний: `activeCategory`, `searchTerm`, `debouncedSearchTerm`, открытый отель для модального окна. В `CartProvider.jsx` хранится список `cartItems`.

## 7. Хуки и правила их применения

Хуки — специальные функции React, позволяющие компонентам использовать возможности React. Названия встроенных хуков начинаются с `use`: `useState`, `useEffect`, `useContext`.

Хуки вызывают на верхнем уровне React-компонента или собственного хука. Их нельзя вызывать внутри условия, цикла или обычной функции: React должен видеть вызовы хуков в одинаковом порядке при каждом отображении компонента.

Собственный хук — функция с именем, начинающимся на `use`, которая может объединить общий способ работы с React. Например, `useCart()` вызывает `useContext(CartContext)` и возвращает данные корзины. Это упрощает компонент и централизует проверку: нельзя случайно использовать корзину вне ее Provider.

## 8. useEffect: синхронизация с внешним миром

Большая часть интерфейса должна напрямую следовать состоянию. `useEffect` нужен, когда React-компонент должен синхронизироваться с чем-либо вне обычного JSX: хранилищем браузера, таймером, DOM-атрибутом, событием окна или сетью.

```jsx
useEffect(() => {
  // выполнить действие после отображения/изменения
  return () => {
    // при необходимости отменить или очистить действие
  };
}, [зависимость]);
```

Массив зависимостей сообщает, после каких изменений эффект нужно запускать:

- `[]` — после первого появления компонента; cleanup выполнится при его удалении.
- `[value]` — после первого появления и при изменениях `value`. Перед повторным запуском React сначала выполнит cleanup предыдущего эффекта.
- без второго аргумента — после каждого отображения компонента; обычно это нежелательно без конкретной причины.

Эффект не является способом заменить обычные вычисления. Если значение можно вычислить во время отображения компонента из уже имеющихся props/state, обычно не нужно копировать его в дополнительное состояние с `useEffect`.

В режиме разработки `StrictMode` React может дополнительно запускать эффекты и очистку, чтобы выявлять неаккуратную синхронизацию. Поэтому эффект должен корректно убирать созданные им таймеры и обработчики.

## 9. Четыре учебных задания на useEffect

### 9.1 Корзина и localStorage

`localStorage` — небольшое хранилище строк в браузере. Данные остаются после обновления страницы в том же браузере и на том же сайте. Оно не является серверной базой, не передает данные другим устройствам и не предназначено для секретов.

Основные операции:

```js
localStorage.setItem('имя', 'текст');
const text = localStorage.getItem('имя');
localStorage.removeItem('имя');
```

Поскольку хранилище хранит строки, для массивов и объектов применяют JSON:

```js
localStorage.setItem('cart', JSON.stringify(cartItems));
const cartItems = JSON.parse(localStorage.getItem('cart') || '[]');
```

`JSON.stringify` преобразует значение JavaScript в текст, `JSON.parse` — текст обратно в значение. Поврежденный текст может вызвать ошибку, поэтому чтение обернуто в `try/catch`.

В `CartProvider.jsx` начальное состояние читается при создании состояния:

```jsx
const [cartItems, setCartItems] = useState(() => {
  try {
    const saved = localStorage.getItem(CART_STORAGE_KEY);
    return saved ? JSON.parse(saved) : [];
  } catch {
    return [];
  }
});
```

Функция передается в `useState`, чтобы React использовал ее как ленивую инициализацию: значение надо прочитать при инициализации, а не заново при каждом отображении. Другой эффект сохраняет состояние:

```jsx
useEffect(() => {
  localStorage.setItem(CART_STORAGE_KEY, JSON.stringify(cartItems));
}, [cartItems]);
```

`[cartItems]` значит, что запись происходит при первом эффекте и при изменении корзины. Ключ `booker_cart_items` позволяет найти запись в инструментах разработчика браузера: Application/Storage → Local Storage.

### 9.2 Поиск с задержкой (debounce)

Если применять фильтр после каждого символа, интерфейс выполняет поиск много раз подряд. Debounce откладывает действие и выполняет его только тогда, когда пользователь сделал паузу заданной длины.

В `HotelList.jsx` используются две величины:

- `searchTerm` — то, что прямо сейчас находится в поле ввода.
- `debouncedSearchTerm` — запрос, который уже разрешено использовать для фильтрации.

При изменении `searchTerm` эффект ставит таймер на 500 мс. Если до истечения этих 500 мс приходит новый ввод, React сначала вызывает cleanup: `clearTimeout(timer)` отменяет старый запуск. Затем ставится новый таймер. Так поиск выполняется после паузы, а не после каждого быстрого нажатия.

```jsx
useEffect(() => {
  const timer = setTimeout(() => {
    setDebouncedSearchTerm(searchTerm);
    setIsDebouncing(false);
  }, 500);

  return () => clearTimeout(timer);
}, [searchTerm]);
```

Фильтр использует `debouncedSearchTerm`, а поле ввода — `searchTerm`. Это разделение и создает задержку. При очистке поля запрос и индикатор также сбрасываются.

### 9.3 События окна, Escape и cleanup

Обработчик клавиатуры можно зарегистрировать на `window`, чтобы Escape закрывал диалог независимо от того, какой элемент получил фокус:

```jsx
useEffect(() => {
  if (!isOpen) return;

  function handleKeyDown(event) {
    if (event.key === 'Escape') closeDialog();
  }

  window.addEventListener('keydown', handleKeyDown);
  return () => window.removeEventListener('keydown', handleKeyDown);
}, [isOpen, closeDialog]);
```

`addEventListener` подписывает код на событие. Если обработчик не снять, он может продолжать вызываться после закрытия интерфейса или удаления компонента. Cleanup делает `removeEventListener` с тем же типом события и той же ссылкой на функцию. Поэтому `handleKeyDown` объявлена внутри эффекта и используется в обоих местах.

В `BookingCart.jsx` Escape закрывает панель корзины только пока она открыта. В `HotelList.jsx` клавиша Escape закрывает активный диалог подробностей или бронирования. `Header.jsx` подписывается на `resize`, чтобы реагировать на изменение ширины окна, и удаляет подписку при размонтировании.

### 9.4 Переключение темы

`ThemeProvider.jsx` хранит `theme` со значением `light` или `dark`. Кнопка в `Header.jsx` вызывает `toggleTheme`, который меняет значение состояния. Эффект реагирует на смену темы:

```jsx
useEffect(() => {
  document.documentElement.setAttribute('data-theme', theme);
  localStorage.setItem(THEME_STORAGE_KEY, theme);
}, [theme]);
```

`document.documentElement` — корневой HTML-элемент `<html>`. Эффект устанавливает ему атрибут, например `data-theme="dark"`, и сохраняет выбор. В `src/styles/index.css` CSS-переменные для темной схемы объявлены в селекторе `[data-theme='dark']`. Компоненты используют переменные вроде `--bg-page` и `--text-main`, поэтому смена атрибута меняет палитру.

При запуске Provider сначала пытается прочитать сохраненную тему; если записи нет, проверяет системную настройку браузера `prefers-color-scheme`. Ошибки чтения/записи хранилища обрабатываются, чтобы приложение могло работать и при недоступном `localStorage`.

## 10. Context: общие данные для многих компонентов

Props подходят, когда родитель напрямую передает данные дочернему компоненту. Но если, например, корзина нужна в шапке, карточках и выдвижной панели, пришлось бы передавать ее через промежуточные уровни. Передача props через компоненты, которым данные не нужны, называется prop drilling.

Context позволяет создать общий канал данных для части дерева компонентов. В React обычно есть три элемента:

1. `createContext` создает объект контекста.
2. Provider помещает `value` в доступное для потомков дерево.
3. `useContext` читает ближайшее значение этого контекста.

В проекте `CartContext.js` создает контекст, `CartProvider.jsx` владеет `cartItems` и функциями корзины, а `useCart.js` читает контекст. Любой компонент внутри Provider может вызвать `useCart()`.

```jsx
const cart = useCart();
cart.addToCart(hotel);
```

Собственный хук `useCart` также проверяет, что компонент находится внутри `CartProvider`, и выводит понятную ошибку, если это не так. Аналогично устроены `useAuth`, `useNavigation` и `useTheme`.

`AppProviders.jsx` вкладывает Providers друг в друга, а `App.jsx` оборачивает ими основную часть приложения. Любой потомок `AppProviders` получает доступ к их значениям. Компонент вне Provider такого доступа не имеет.

Context не заменяет все props и не является автоматически серверной базой. Локальные данные одного компонента удобно держать в его `useState`; общие данные — в подходящем Provider; конкретные параметры дочернего компонента — в props.

## 11. Как устроен Booker: путь от входа до интерфейса

### Точка входа

`index.html` содержит элемент с id `root`. `src/main.jsx` находит его через `document.getElementById('root')` и просит React отрисовать `<App />` внутри. `StrictMode` включает дополнительные проверки для разработки. Глобальный CSS подключается рядом.

### App и выбор страницы

`src/App.jsx` оборачивает интерфейс в `AppProviders`. В `MainContent` читается `currentPage` через `useNavigation`. На домашней странице выводятся `Hero`, `HotelList` и `Services`; при выборе входа или регистрации показывается соответствующая форма. `Header`, `Footer` и `BookingCart` присутствуют на всех этих экранах.

### Каталог и фильтрация

`src/data/hotels.js` экспортирует массив объектов отелей. `HotelList.jsx` создает кнопки категорий и вычисляет `filteredHotels` из исходного массива, активной категории и отложенного поискового запроса. Затем `.map()` строит `HotelCard` для каждого результата. При отсутствии результатов показывается пустое состояние.

### Корзина и вычисления

`CartProvider.jsx` хранит массив объектов. У каждого элемента есть `hotel`, `roomsCount`, `nights` и `selected`. Функции Provider добавляют, изменяют и удаляют элементы. `BookingCart.jsx` отображает значения и считает стоимость выбранных отелей: цена умножается на количество комнат и ночей.

### Вход и регистрация

`Login.jsx` и `Register.jsx` управляют полями формы с помощью состояния. `AuthProvider.jsx` предоставляет действия авторизации. `src/utils/auth.js` содержит логику демо-пользователей и сохранения. Поскольку серверной проверки нет, это учебная демонстрация, не настоящая система безопасности.

### Стили

CSS-файлы разделены по частям интерфейса: `Header.css`, `HotelList.css`, `HotelCard.css`, `BookingCart.css` и другие. `src/styles/index.css` задает общие правила и переменные цветов. JSX задает структуру и поведение, CSS — внешний вид.

## 13. Как самостоятельно изучать и менять проект

1. Запустите `npm run dev` и посмотрите на сайт.
2. Откройте `src/main.jsx`, затем проследите путь к `App.jsx` и компонентам.
3. Измените заголовок в `HotelList.jsx` и убедитесь, что Vite обновил страницу.
4. Добавьте временный `useState` в небольшой компонент и выведите значение на экран.
5. Посмотрите, какие props передаются в `HotelCard` из `HotelList`.
6. Добавьте отель в корзину, обновите страницу и проверьте, что он сохранился.

## 14. Словарь

- **Браузер** — программа, которая показывает сайт и выполняет его JavaScript.
- **Frontend** — код интерфейса, выполняющийся в браузере пользователя.
- **SPA** — приложение, которое переключает экраны без полной перезагрузки документа.
- **Компонент** — повторно используемая функция, возвращающая участок интерфейса.
- **JSX** — синтаксис для описания разметки интерфейса внутри JavaScript.
- **Props** — входные данные компонента от его родителя.
- **State** — изменяемая память компонента, влияющая на отображение.
- **Хук** — функция React, которая подключает компонент к состоянию, контексту или эффектам.
- **Эффект** — синхронизация компонента с внешней системой после отображения.
- **Cleanup** — функция очистки, отменяющая таймер или снимающая подписку эффекта.
- **Context** — способ передать общее значение потомкам без прокидывания через каждый уровень.
- **Provider** — компонент, который предоставляет значение контекста своим потомкам.
- **localStorage** — строковое хранилище браузера, сохраняющее значения между перезапусками страницы.
- **Debounce** — ожидание паузы в потоке событий перед выполнением действия.
- **DOM** — объектное представление HTML-страницы, доступное JavaScript.
- **Сборка** — подготовленные оптимизированные файлы приложения для размещения на хостинге.
